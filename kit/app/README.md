# تشغيل واجهة المساعد النصية والصوتية

من مجلد `kit` وبعد تفعيل `.venv`:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

شغّل نسخة واحدة وworker واحدًا؛ حالة الجلسات والأقفال في ذاكرة العملية.
خدمة العيادة تعمل منفصلة على `8101`. نقطة `/health` تختبر خدمة المساعد
فقط، ولا تختبر اتصال العيادة أو LLM.

افتح توثيق الطلبات التفاعلي: http://127.0.0.1:8000/docs

النقاط المنفذة:

- `GET /health`
- `POST /api/chat` مع `session_id` و`message`، واختياريًا `user`.
- `POST /api/approve` مع `session_id` و`action_id` و`approved` كقيمة boolean.
- `POST /api/voice` مع multipart يحتوي `session_id` وملف `audio` بصيغة WAV أو MP3.

استخدم `session_id` نفسه لكل رسائل المحادثة وقرار الموافقة.
نقطة الموافقة لا تقبل تفاصيل الحجز من المتصفح؛ تقرأ العملية المحفوظة.
الموافقة الحقيقية قد تنفذ كتابة عبر MCP؛ الاختبار أدناه يستخدم بوابة وهمية فقط.

```powershell
python test_api.py
```

لتشغيل الواجهة النصية، افتح terminal ثانيًا من `kit`:

```powershell
python ui/app_ui.py
```

الرد يعرض الخيارات المرقمة. يقبل الاختيار مثل `option 2` أو `option two`
أو `الخيار الثاني`. الصوت يستخدم نفس الجلسة وفحوص السلامة ومسار المحادثة النصية.
نطق الرد من المتصفح؛ `audio_b64` و`audio_mime` تساويان `null` في هذا الوضع.
يوجد زر Replay لإعادة سماع الرد إذا منع المتصفح التشغيل التلقائي.

تفاصيل التشغيل والديمو وحدود الأخطاء والاختبارات في [VOICE_DEMO.md](../VOICE_DEMO.md).
