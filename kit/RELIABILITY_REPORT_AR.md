## تدفق الصوت الجديد وحماية الحالة

1. اختر العربية أو English، وسجّل أو ارفع ملفًا، ثم اضغط **Transcribe current recording**.
2. `/api/voice` يفحص الملف، ويفرغه، ويتحقق من خط اللغة. يعيد transcript مع
   `needs_transcript_confirmation=true` و`transcript_token`، دون تشغيل Intake أو Graph.
3. راجع النص. إذا لم يكن كلامك، أعد التسجيل أو استخدم الإدخال النصي؛ لا تضغط Use transcript.
4. **Use transcript** يرسل token فقط إلى `/api/voice/confirm`. لا يستطيع العميل استبدال
   النص داخل هذا الطلب. ينتهي token بعد خمس دقائق أو استبداله بتسجيل/رسالة/قرار أحدث.
5. يطابق الخادم نسخة AgentState وجيل التسجيل تحت قفل الجلسة، ثم يشغل مسار chat نفسه.
   الرد المتأخر أو تأكيد قديم لا يغير الموعد أو الهوية أو الموافقة الحالية.
6. هذا تأكيد لصحة النص فقط. الحجز لا يزال يحتاج زر Approve لمسار `/api/approve`،
   وقول yes أو نعم في المحادثة لا ينفذ كتابة.

بصمة الملف تكشف تكرار البايتات نفسها داخل الجلسة، وليست إثباتًا أن الميكروفون التقط
الكلام الحالي؛ ملف قديم مختلف البايتات أو نص خاطئ بنفس اللغة قد يجتاز فحص الإشارة.
لهذا تُطلب مراجعة كل تفريغ، بما فيه العبارات القصيرة الصحيحة، بدل ادعاء كشف الهلوسة.
الواجهة تمسح token عند بدء تسجيل أو رفع/مسح ملف جديد، ولا ترسل أحداث stop/upload آليًا.

المسار يفحص PCM 16-bit ويستعمل تحويل STT الموجود إلى 16kHz mono قبل الرفع.
لا نضيف قصًا صوتيًا أو VAD أو مكتبة جديدة. رفض الملف لا يعتمد على عدد الكلمات، وتغطي
الاختبارات 3 ونص وthree thirty وyes وoption two و3:30. فحص الصمت المحلي خاص بـWAV؛
MP3 يظل بحاجة لفحص المزود ومراجعة النص. التسجيل الأصلي وحدود التقاطه لم تُفحص لغيابه.

## هوية المريض وولي الأمر

`valid_patient_name(name)` يقبل أحرفًا عربية ولاتينية وعلامات اسم معتادة، ويتطلب جزأين
على الأقل. يرفض الأرقام والأسماء الفارغة ووصف القرابة والبدائل الواضحة، وليس خدمة تحقق
هوية رسمية. الاسم الصحيح المكتوب بخطأ لا يمكن كشفه بهذه القواعد وحدها.

`third_party_request(message)` يميز طلبًا لشخص آخر؛ لا يحول my son إلى patient_name.
مسار تبديل المريض يمسح الهاتف والاسم والاختيار والموافقة القديمة ونتيجة بحث الهوية.
إذا ذكر رقمًا جديدًا صراحة يُجمع من جديد؛ لا يُورث رقم مستنتج من الدور السابق.
عند تغيير الاسم وحده نعامل الأمر بحذر كتغيير هوية، فيُطلب إعادة التحقق بدل الاحتفاظ
برقم قد يكون لمريض آخر؛ لذلك تغير توقع اختبار تصحيح الاسم السابق عمدًا.

حجز الشخص لابنه لا يثبت أن الابن قاصر: يُطلب عمره إن لم يكن معروفًا. العمر دون16 يبقي
شرط التحقق من ولي الأمر، وتبقى pediatrics_visit محجوبة وفق مسار A الحالي. لم أضف
صلاحية حجز أطفال أو سياسة guardian بديلة؛ عند الحاجة يوجّه الرد للتواصل مع العيادة.
بحث الهاتف لشخص يحجز لغيره لا يملأ اسم المريض باسم صاحب الهاتف. استكمال تحقق ولي
الأمر عبر الواجهة ما زال مسؤولية مسار المشروع المشترك، وليس ميزة مكتملة هنا.

الخادم. استمرار واجهة قديمة دون جلسة يظهر session_reset، بما فيه مسار مراجعة الصوت.

`reliability_live_intake.json` تحفظ القياسات والحالات المنظمة فقط، دون transcript أو أسماء
أو أرقام هواتف أو مفاتيح. تتضمن قياسات MCP بدء عملية stdio ومصافحة MCP وطلب HTTP،
ولا تفصل هذه الأجزاء. يبدأ Gateway الحالي عملية MCP لكل أداة؛ لم أعد كتابة بنيته المشتركة.

ثبت الآن أن الاتصال بالعيادة غير متاح، ولم أبدأها أو أعد تشغيلها أو أغير بياناتها. لذلك
هذه أزمنة فشل وليست أداء بحث ناجح. LLM/STT هما أكبر من فحص الصوت بكثير، وتضاف
كلفة MCP عند البحث. تخطي LLM للاختيار القصير، وإعادة استعمال القراءة المطابقة داخل
طلب واحد، يقللان الاستدعاءات دون cache دائم قد يخفي تغير تقويم العيادة أو التوافر.
لا يوجد دليل يحدد سبب كل 503 قديم؛ السجل الجديد يحفظ نوع الاستثناء فقط لمتابعة ذلك.
