# ديمو Zaytoun بالصوت — من التسجيل إلى الموافقة المعلقة

هذه المرحلة تعيد استخدام Gradio وOpenRouter STT ونطق المتصفح الموجودة.
لا توجد مكتبات جديدة، ولا تنزيل نماذج، ولا خدمة TTS مدفوعة جديدة.

## تشغيل الخدمات

نفذ الأوامر من `kit` بعد تفعيل `.venv`، وكل خدمة في terminal مستقل.
إذا كانت إحدى الخدمات تعمل بالفعل، استخدمها بدل تشغيل نسخة أخرى على المنفذ نفسه.

العيادة المحاكية، بتاريخ مناسب لعينات المدرّب:

```powershell
$env:CLINIC_TODAY="2026-11-02"
python -m uvicorn services.clinic_api:app --host 127.0.0.1 --port 8101
```

خادم المساعد (worker واحد لأن SessionStore في RAM):

```powershell
$env:STT_PROVIDER="openrouter"
$env:TTS_PROVIDER="browser"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

الواجهة:

```powershell
$env:GRADIO_ANALYTICS_ENABLED="False"
$env:APP_URL="http://127.0.0.1:8000"
python ui/app_ui.py
```

افتح http://127.0.0.1:7860 واسمح للميكروفون. يبقى الإدخال النصي متاحًا دائمًا.
استخدم زر Replay إذا لم يُسمع الرد تلقائيًا. توفر الأصوات العربية يعتمد على المتصفح والجهاز.
المفتاح الحالي يُقرأ من `.env`؛ لا تضعه في الكود أو الديمو أو السجلات.
التفريغ الحقيقي يستعمل رصيد OpenRouter الحالي، بينما الاختبارات أدناه لا تستعمله.

## خطوات العرض اليدوي

1. سجّل: “I would like a dental checkup on November 3, 2026 after 3 PM. Any doctor is fine.”
2. أوقف التسجيل. تحقق من transcript، والخيارات المرقمة، وحالة `slots_proposed`، وسماع الرد.
3. سجّل “option two”. يجب أن يُحفظ معرّف ثاني موعد في القائمة الحالية.
4. سجّل “My name is Test Patient and my phone number is zero five nine nine, zero zero zero, nine nine nine.”
5. تحقق من `awaiting_approval` وملخص الخدمة والتاريخ والوقت والطبيب وبيانات المريض.
6. توقف هنا لعرض voice-to-approval دون كتابة. يمكن ضغط Reject لإلغاء الطلب.

إذا لم تتوفر مواعيد لهذا التاريخ، اعتمد التاريخ والخيارات الفعلية التي أعادتها العيادة.
لا تضغط Approve أثناء اختبار عدم الكتابة؛ هذا الزر ينفذ الموافقة الحقيقية عبر MCP.
تسجيل “yes” أو “نعم” وحده لا ينفذ الحجز. القرار الصريح عبر `/api/approve` فقط.

للعربية: جرّب طلبًا عربيًا ثم “الخيار الثاني”. تدعم هذه المرحلة تفريغ العربية
والاختيار بالعربية؛ بعض رسائل سير العمل تبقى بالإنجليزية كما في النسخة النصية.

بديل الميكروفون: ارفع `samples/audio/en_02_vague_friday.wav` لطلب توضيح،
أو `samples/audio/en_01_book_tuesday.wav` للبحث، أو العينة العربية المناسبة.

## تجربة HTTP

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/voice -F "session_id=voice-demo-1" -F "audio=@samples/audio/en_02_vague_friday.wav"
```

الرد يتضمن حقول ChatResponse و`transcript` و`audio_b64` و`audio_mime`.
مع `TTS_PROVIDER=browser` حقلا الصوت `null`؛ Gradio ينطق `reply` باستخدام speechSynthesis.
عميل HTTP وحده لا يشغّل نطق المتصفح.

## نتيجة التحقق الفعلي في 30 أكتوبر 2026

تم اختبار `/api/voice` عبر HTTP مع OpenRouter الحالي وقراءات MCP الحقيقية للعيادة المحاكية:

- `en_02_vague_friday.wav` أعاد transcript وطلب توضيح الخدمة، مع HTTP 200.
- `en_01_book_tuesday.wav` أعاد خيارين بتاريخ 2026-11-03 عند 16:30 و18:00.
- تسجيل تجريبي لعبارة “option two” باستخدام صوت Windows المثبت أصلًا فُرغ إلى “Option 2”.
- الجلسة نفسها وصلت إلى `awaiting_approval` للموعد `SL-20261103-1800-dr_khoury`.
- لم يرسل الاختبار `/api/approve` ولم ينفذ `create_booking` أو ينشئ حجزًا.
- الواجهة والخادم أعادا HTTP 200. سماع صوت المتصفح والتسجيل بميكروفون المستخدم يحتاجان التحقق اليدوي.
- تم رفع العينة القصيرة عبر handler الصوت في Gradio الفعلي أيضًا؛ رجعت المحادثة وtranscript وحالة `awaiting_details` بنجاح.
- قبل إصلاح التطبيع العربي، العينة `ar_01_book_cleaning.wav` أعادت تفريغًا عربيًا وHTTP 200، ثم وصلت إلى `awaiting_details`.

هذه نتائج تقويم تلك التجربة، وليست مواعيد ثابتة تُعرض أو تُحفظ في كود التطبيق.

إصلاح لاحق للتطبيع العربي: `normalize_date` أصبح يدعم “2 نوفمبر 2026”
و“يوم الاثنين 2 نوفمبر” والأرقام العربية، مع رفض اليوم المتعارض والتاريخ الماضي.
تستخدم السنة الناقصة سنة العيادة. مطابقة الخدمة توحد “الأسنان/أسنان” دون تغيير أسماء الأطباء.
تم التحقق عبر HTTP فعليًا من النص:
“بدي اعمل فحص اسنان يوم الاثنين 2 نوفمبر 2026 بعد الساعة 3 العصر عند اي دكتور متاح”.
أعاد `slots_proposed` وخمسة مواعيد بتاريخ 2026-11-02 بعد الثالثة، كما بقي الطلب الإنجليزي ناجحًا.
التجربة كانت بقراءات فقط دون إرسال موافقة أو إنشاء حجز.

## أخطاء وحدود هذه المرحلة

- تسجيل فارغ أو قصير أو WAV تالف: `422` مع طلب إعادة التسجيل أو الكتابة.
- صيغة أخرى مثل WebM/Ogg: `415`؛ الواجهة مضبوطة لإنتاج WAV.
- حجم أكبر من 10 MB: `413` قبل إرساله للتفريغ.
- تعذر STT: `503`؛ انتهاء مهلة التفريغ (45 ثانية) أو المعالجة (60 ثانية): `504`.
- النص الفارغ لا يصل إلى Graph، وحالة الجلسة والموافقة السابقة تبقيان محفوظتين.
- أخطاء الصوت ترجع `reply` واضحًا وحقول العقد؛ الواجهة تحتفظ بأزرار الموافقة السابقة.
- فشل TTS لا يعيد Graph؛ النص يبقى متاحًا. لا يستدعي المحول Piper أو ينزل أصواتًا حتى لو ضُبط Piper بالخطأ.
- انتهاء مهلة `asyncio.to_thread` لا يستطيع إيقاف thread الشبكة بالقوة؛ لا نضيف إعادة محاولة تلقائية فوق محول STT الموجود.
- STT وTTS ليسا مصدرًا للمواعيد أو للموافقة. كل transcript يمر بفحوص السلامة المعتادة.
- نسخة النص الأصلية من transcript تبقى معروضة؛ تحويل كلمات الأرقام يحدث محليًا داخل محلل الاختيار فقط.
